# CI

`.github/workflows/ci.yml` runs on every push to `main` and on every pull request. It is five
independent jobs — one per check — so a red X tells you immediately which check failed, and each
maps to a command you can run locally:

| CI job | Command to reproduce locally | Fails when |
|---|---|---|
| spell check | `uvx typos` | a typo is found in code, comments, or docs |
| rustfmt | `cargo fmt --check` | any file is not in canonical format |
| clippy | `cargo clippy --all-targets --locked -- -D warnings` | any lint warning fires |
| tests | `cargo test --locked` | a unit or integration test fails |
| cargo deny | `cargo deny check` | a dependency has an advisory, bad license, or odd source |

Details worth knowing:

- **Warnings are errors.** `-D warnings` means a clippy warning locally *will* fail CI — never
  assume a warning is pre-existing; `main` is kept warning-free.
- **`--locked` everywhere.** CI builds with the committed `Cargo.lock`; if it is stale, CI
  fails. Keep the lockfile committed and updated with `cargo update --precise`.
- **Two architectures.** Tests run on x86_64 and aarch64 (mirroring the Raspberry Pi / Jetson
  reference platforms).
- **Superseded runs are cancelled.** Pushing a new commit to a PR cancels the in-flight run.

The fix loop is always the same: reproduce the failing command locally from the table above,
fix, push again.
