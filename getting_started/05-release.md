# Release

Releases are fully automated by [cargo-dist](https://axodotdev.github.io/cargo-dist). A human
does two things; GitHub Actions does the rest.

## What you do

1. Bump `version` in `Cargo.toml` (and `Cargo.lock`), merge to `main`.
2. Push a matching tag:

```bash
git tag v0.1.2
git push origin v0.1.2
```

## What happens then

The tag triggers `.github/workflows/release.yml` (generated by cargo-dist — do not hand-edit
it; regenerate with `dist init` after changing `dist-workspace.toml`):

1. **plan** — `dist` parses the tag into a version and computes the build matrix.
2. **build-local-artifacts** — builds release binaries for each target (x86_64 and aarch64
   Linux, inside manylinux containers so they run on glibc ≥ 2.28), packaged as archives with
   checksums.
3. **build-global-artifacts** — builds the platform-agnostic pieces, e.g., the shell installer.
4. **host** — uploads everything and creates the GitHub Release with generated notes.

The workflow also runs in plan-only mode on pull requests, so a broken release config surfaces
before tagging.

## Configuration

`dist-workspace.toml` is the single config: cargo-dist version, targets, installers, and the
manylinux container setup. Change it there, then run `dist init` to regenerate the workflow.
